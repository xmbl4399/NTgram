## v15 实测失败原因（本次修复的根因）

用本地 Gemma-4-E4B 跑 v15 采样 3 次，**3/3 都出现同一种错误**：

```
（她猛地停下脚步…）

> 我还好吗？ 唔... 哼！
>
> （她噘起嘴，用手背轻轻蹭了蹭脸颊，做出一个夸张的表情。）
>
> 當然是很好啦！ 誰敢說我不好？
```

模型把**动作行也加了 `>`**，还用**只含 `>` 的空行**在块内分段。
结果：整段回复合并成**一个 blockquote**，渲染出来就是「台词和动作揉在一起，只有一条竖线」。

| 现象 | 真实原因 |
|---|---|
| 台词+动作揉成一块 | 动作行被模型加了 `>`（v15 只说"不加 >"，没给反例，压不住） |
| 块内出现空档 | 模型自创 `>` 空行（`>` 空行仍是同一 blockquote 的行） |
| **不是** lazy continuation | 指标「引用块后吞行」= 0 处，v15 担心的吞行并未发生 |

**v16 的修法**：把「动作行绝对不能有 `>`」提升为独立硬规则并配 3 条 ✗/✓ 反例；显式禁止空的 `>` 行。

## 配套的渲染层兜底（已改代码）

即便提示词写清楚，模型仍可能写出「台词块紧贴动作行、中间没空行」，
或用「只含 `>` 的行」分段，触发 CommonMark 的 lazy continuation
把动作吸进引用块。`message_content_widget.dart` 现在在渲染前做一次归一化
（**`_normalizeQuoteBlocks`**，两趟处理）：

1. **剥前缀**：`>` 行体若以 `（` 开头，说明模型给动作行也加了 `>` → 去掉 `>` 还原成正文
2. **断懒续行**：在「引用行 → 非引用行」相邻交界处补一个空行（代码块内不动）

连续的 `>` 行不拆开，仍合并为同一个引用块；过程幂等，可重复执行。
探针：`tools/quote_fix_probe.dart`（4 组用例全绿）。
