## 一、为什么要改：v25 在三张卡上全线失守

用 `tools/run_cards.py` 对三张真实角色卡各测 3 次首次输出：

| 卡 | 卡总字数 | `>` 引导 | 长度 | 外语泄漏 |
|---|---|---|---|---|
| Ruby | 6.5k | 3/3 | 500+ 字 | 0 |
| Aqua | 11.9k | **1/3** | 503–829 字 | **英文 68–116 词** |
| Yuki | 23.9k | **2/3** | 517–597 字 | **韩文 2/3** |

三个病症：

1. **长度锚失效** —— 系统提示写「80–160 字」，实际 500–829 字（超上限 3–5 倍）
2. **外语泄漏** —— Aqua 输出整段英文旁白；Yuki 台词写成韩文（`> "응. 나는 읽고 있다."`）
3. **首轮 `>` 失手** —— 两卡的 run#1 都完全不用 `>`，把台词揉进 `*...*` 块

**统一根因：提示词在跟卡内的 `mes_example` 抢地盘，且抢不过。**

| 卡 | mes_example 教什么 | 提 `>` 吗 |
|---|---|---|
| Ruby | 反引号包内心 + 「永远第三人称」 | ❌ |
| Aqua | `"台词" *她笑着说*` | ❌ |
| Yuki | 明文规则：`对话用双引号` / `动作用星号` | ❌ |

三张卡一致教 `"台词" *动作*`，没有一张提 `>`。示例的 few-shot 示范权重压倒末尾的规则句。
语言漂移同理：Yuki 的 description 是 10830 字全英文 + 英文示例，模型在英文语境里漂出英/韩文。

## 三、四条可复用的规律

### 1. 点名作废示例，是唯一能压过 few-shot 的做法
A 变体只加了这一条（+40 字），韩文立刻从 53 → 0。**「以角色卡设定为准」这种尊重式措辞在格式上是无力的**——v25 就是这么写的，结果模型全听示例的。

### 2. 长度上限必须往下压，往上放会反向激励
把 160 改成 200–300 之后，字数**飙到 775–859**（C 变体）。模型会把「上限」当新目标。
E4 把上限从 250 压到 180，字数反而从 521–570 降到 289–429。

### 3. 长度锚与台词密度锚必须配对
| 给法 | 后果 |
|---|---|
| 只给长度上限（E2） | 台词压到 1 句 |
| 只给密度（E3） | 字数反弹到 521–570 |
| **两个都给（E4）** | 289–429 字且台词保持 2 句 ✅ |
| 两个都不给（E5） | 字数崩回 422–648 |

「至少 2 句 `>` 台词」看似会拉长，实际是**压长度的把手**——它让模型的注意力从「展开描写」转到「把台词写出来」。

### 4. 首轮失手要在系统提示里点名
只改历史后指令（A）仍有 1/3 首轮失手。在系统提示的台词规则后补一句「从第一条回复起就必须遵守」（B）后 6/6 无失手。

### 系统提示词（332 字符，比 v25 +13）


## 四条关键发现

### 1. 交替结构天然比分块长
多出一个动作段，字数普遍从 v27 的 302 涨到 440–470。**这是结构性代价**，不是提示词失误。

否则模型会把预算全花在动作上（H3 → H5 降 32 字）。

不加约束时会产出 `(（...）)` 这种畸形两层括号。加"不要两层括号套起来"后消除。

## 核心突破：把「描写类型」和「字数锚」彻底拆开
